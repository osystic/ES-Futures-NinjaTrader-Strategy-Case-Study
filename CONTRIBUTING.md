# Contributing

This repository is a sanitized OSYSTIC public engineering case study, not an open-source copy of the client delivery.

## Allowed contributions

Contributions may improve public documentation, diagrams, accessibility, validation controls or factual corrections. Do not submit NinjaScript/C# strategy source, raw NinjaTrader evidence, private datasets, client identity, commercial information, private repository links or unsupported performance claims.

## Workflow

1. Open an issue with outcome, acceptance criteria, evidence and disclosure impact.
2. Create `feat/<issue>-...`, `fix/<issue>-...` or `docs/<issue>-...` from `main`.
3. Open a draft PR early.
4. Run the public-showcase validation.
5. Map claims to approved evidence and complete disclosure review.
6. Squash merge after review using `Closes #<issue>`.

Public claims, client disclosure, visibility changes and publication/withdrawal decisions require founder approval.

## Claims standard

Technical completion is not a profitability claim. The published status must remain consistent with the approved evidence: 0/11 eligible registered candidates, Stage B not opened, STOP_L for research/paper trading only and live/funded NO-GO.
