# Engineering lessons

## Technical functionality is not profitability

A strategy can compile, place orders, manage stops and respect risk controls while still lacking a stable trading edge. Those are separate acceptance questions and should be reported separately.

## Safety locks affect the shape of evidence

A permanent internal drawdown lock can suppress later trades in a test window. That behavior must be interpreted as part of the architecture, not removed merely to improve trade count.

## Pre-registration protects decisions

Fixing candidates, windows and gates before reviewing results reduces the temptation to rescue a weak model after validation.

## Aggregate profit can hide regime failure

A slightly positive combined total did not erase a negative development period, a poor individual validation year or weak minimum-window profit factor.

## Native evidence still matters

Bar-based external simulators are useful for rapid research, but native NinjaTrader runs remain necessary for fill-engine and managed-order confirmation.

## Honest NO-GO is a deliverable

Rejecting every candidate can be the correct professional outcome. The reusable value is the engineered platform, evidence trail, decision framework and clear path for prospective reassessment.
